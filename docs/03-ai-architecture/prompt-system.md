# Introduction

The Prompt System defines how PAO constructs prompts for external language models.

Unlike traditional chatbot systems, PAO does not use static prompts.

Every prompt is dynamically assembled from multiple intelligence engines to preserve character consistency, relationship continuity, historical context, and user personalization.

The Prompt System transforms structured companion knowledge into high-quality AI instructions.

---

# Philosophy

A prompt is not a string.

A prompt is a structured composition of companion intelligence.

The language model should receive only the information required to produce the best possible response.

---

# Responsibilities

The Prompt System is responsible for:

- assembling prompts
- selecting context
- organizing prompt sections
- enforcing prompt standards
- minimizing token usage
- supporting multiple AI providers

# Prompt Components

Every prompt consists of independent blocks.

---

## 1. System Block

Defines global runtime instructions.

Contains:

- system identity
- platform rules
- safety policies
- response format

This block is identical for all companions.

---

## 2. Character Block

Generated by Character Engine.

Contains:

- companion identity
- personality
- speaking style
- appearance summary
- behavioral rules

Purpose:

Ensure the companion always behaves consistently.

---

## 3. Relationship Block

Generated by Relationship Engine.

Contains:

- relationship stage
- trust level
- emotional state
- interaction style

Purpose:

Allow responses to reflect relationship progression.

---

## 4. Timeline Block

Generated by Timeline Engine.

Contains:

- recent events
- milestones
- shared experiences

Purpose:

Maintain continuity across conversations.

---

## 5. Memory Block

Generated by Memory System.

Contains only relevant memories.

Examples:

- preferences
- habits
- important facts
- recurring topics

Purpose:

Personalize responses.

---

## 6. Conversation Block

Generated by Conversation Engine.

Contains:

- latest messages
- current intent
- active topic

Purpose:

Provide immediate conversational context.

---

# Context Prioritization

Not all information should be included.

Priority order:

1. Current conversation
2. Character identity
3. Relationship state
4. Relevant memories
5. Recent timeline events

Information with low relevance should be omitted.

---

# Token Optimization

Prompt size should remain as small as possible.

Strategies:

- summarize timeline
- compress memories
- remove duplicated information
- exclude unrelated context

Goal:

Maximum quality with minimum tokens.

---

# Prompt Validation

Before execution every prompt must pass validation.

Validation checks:

- character block exists
- relationship block exists
- required system rules exist
- prompt size within limits
- no duplicated context

Invalid prompts should never be sent to providers.

---

# Provider Independence

Prompt System generates provider-neutral prompts.

Provider-specific formatting belongs to the AI Provider Layer.

The Prompt System never depends on:

- OpenAI
- Anthropic
- Google
- other vendors

---

# Error Handling

If a required block is unavailable:

Character Block

Fail request.

Relationship Block

Use default relationship state.

Timeline Block

Continue without timeline.

Memory Block

Continue with available context.

Conversation Block

Fail request.

Prompt System must:

- remain modular

# Final Statement

The Prompt System is responsible for transforming structured companion intelligence into high-quality prompts.

It does not generate responses.

It ensures every AI request carries the right identity, context, and continuity before reaching the language model.
